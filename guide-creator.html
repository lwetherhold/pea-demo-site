🤔 What is a Creator Agent?

A Creator Agent is an AI agent designed to help you build other AI agents. It acts as an expert consultant that:

  • Researches best practices, frameworks, and domain knowledge
  • Analyzes your requirements and constraints
  • Recommends optimal approaches based on research
  • Asks clarifying questions to fill gaps in requirements
  • Designs complete agent architectures (system prompts, memory, tools)
  • Creates the actual agents via API or platform tools
  • Documents the entire process for replication
💡 Key Insight: The most important part of working with a Creator Agent is being specific about what you need while remaining open to the agent's suggestions and research. The Creator Agent knows best practices you might not be aware of!

🌐 Working on Any Platform

A Creator Agent can exist on any AI platform. Here's how the workflow adapts:

Platform Comparison

Platform Creator Capabilities Output Limitation
Claude (Projects) Full research, design, documentation Cannot create agents programmatically - you build manually
ChatGPT Research, design, recommendations Cannot create agents - provides instructions
Letta Research, design, AND create agents via tools Full automation possible!
Gemini/Copilot Research, design, documentation Manual implementation required

Universal Workflow

Regardless of platform, the Creator Agent workflow follows this pattern:

  1. Describe Your Need - What agent do you want? What problem should it solve?
  2. Let Research Happen - Allow the Creator to research frameworks, best practices, your domain
  3. Review Recommendations - Creator will present options with pros/cons
  4. Answer Questions - Creator will ask clarifying questions to fill gaps
  5. Approve the Design - Review the proposed architecture before creation
  6. Build or Export - Either Creator builds it (Letta) or you receive instructions (other platforms)
  7. Test and Iterate - Use the created agent and refine with Creator's help

1️⃣ Phase 1: Research & Analysis

What We Did: Creator Agent researched prompt engineering frameworks, construction industry AI use cases, and conversational agent best practices.

Research Conducted:

  • Prompt Engineering Frameworks:
    • CTF Framework (Context, Task, Format) - Simple, 3-part
    • RTCCO Framework (Role, Task, Context, Constraints, Output)
    • RASCEF Framework (Role, Action, Steps, Context, Examples, Format)
    • PRIME Framework (Purpose, Requirements, Instructions, Metrics, Examples)
    • 5C Framework (Clarity, Contextualization, Command, Chaining, Continuous Refinement)
    • 4-Layer Framework (Core Instruction, Context Independence, Model-Agnostic Language, Failure-Resistant Design)
  • Construction Industry AI Use Cases:
    • RFI/submittal automation
    • Safety documentation
    • Bid/proposal writing
    • Client communication
    • Code/regulation research
  • Conversational Prompt Agent Best Practices:
    • Agent system prompts need: Who are you? What do you have? How should you work?
    • Encourage explicit reasoning before tool calls
    • Iterative testing and refinement essential
    • Treat prompts as code: version-controlled, tested, reviewed

How We Did It:

Creator Agent used web_search tool to query official documentation and research papers. Results were synthesized into actionable recommendations.

Why We Did It:

Without research, we might have chosen a framework that doesn't fit the audience (construction professionals new to AI). Research ensured we made informed decisions from the start.

🎯 Key Decisions We Made

Each decision had a rationale based on research or requirements:

Decision Rationale Alternative Rejected
CTF as teaching framework Simple, 3-part structure for beginners in construction RASCEF (too complex for beginners)
RTCCO/RASCEF internally Ensures comprehensive prompts, fills gaps users don't know to ask Just CTF (would miss important prompt elements)
Conversational interview style Transforms agent from template filler to true prompt engineer Direct prompt generation (less personalized)
Construction domain awareness Tailors prompts to industry terminology and workflows Generic prompts (less useful for BIA audience)
Platform-agnostic + specialization Flexibility for users on any AI platform ChatGPT-only (too limiting)
Transfer capability Members won't adopt Letta - need standalone solutions Letta-only (adoption barrier)
Migration assistance Common request to move ChatGPT → Claude Ignore migration (miss user need)
Adaptive tone Professional OR casual based on user preference Fixed tone (might not match user style)

✅ Best Practices When Working with a Creator Agent

  1. Start Broad, Then Narrow - Describe your general need first, then add specifics as the Creator asks questions
  2. Trust the Research - Let the Creator investigate before making decisions; they know what to look for
  3. Be Honest About Constraints - If budget, time, or platform is limited, say so upfront
  4. Provide Context - Who is this for? What problem does it solve? What's the audience?
  5. Ask "Why" - If you don't understand a recommendation, ask for rationale
  6. Iterate - First versions won't be perfect; plan for refinement
  7. Document Together - Work with the Creator to document decisions for future reference
  8. Test Early - Get a working prototype quickly, then refine based on actual usage

⚠️ Common Pitfalls to Avoid

1. Being Too Vague

"Create me an AI agent" → Creator doesn't know where to start. Always describe: purpose, audience, platform, and key features you want.

2. Jumping to Solutions

"Use RASCEF framework" → Let Creator research and recommend. You might miss a better option because you skipped the research phase.

3. Ignoring Platform Constraints

Requesting features a platform can't support wastes time. Be clear about which platform you're targeting so Creator can design within constraints.

4. Not Testing the Output

Assuming the first version is final. Always test the created agent and iterate based on real usage.

5. Skipping Documentation

Forgetting to document decisions means you can't replicate success or learn from mistakes. Build documentation into the process.
